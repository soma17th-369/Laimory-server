# 약관 원문 작성 — 진행 관리

법무 원문이 없어 비어 있는 약관 catalog를 채우는 작업의 단일 관리 문서다.
초안 원문은 `drafts/`에 있고, 이 문서는 상태·결정·미결만 관리한다.

- 추적 이슈 #383
- 최초 작성 2026-08-18, 최종 갱신 2026-08-26
- 사실 근거는 `dev` 코드다. 문서와 코드가 다르면 코드가 권위다.

## 1. 전달 방식 — #320으로 바뀌었다

원문은 **DB에 저장하지 않는다.** `laimory.app`에 버전별 정적 HTML을 게시하고
`term_documents.content_url`이 그 URL을 가리키며, Android는 WebView로 연다.

| 항목 | 값 |
|---|---|
| URL 규칙 | `https://laimory.app/terms/{term-slug}/{term-version}` |
| version 형식 | `1.0`, `1.1`, `2.0` (문자열, exact match). **날짜 아님** |
| seed 컬럼 | `term_type`, `version`, `title`, `content_url`, `effective_at` 5개뿐 |
| URL 생성 | 코드가 역산하지 않는다. **운영 seed가 넣는 값**이다 |
| 게시된 버전 URL | 불변. 개정은 새 version + 새 URL |

`drafts/`의 Markdown이 원문의 source of truth이고, 게시용 HTML은 거기서 렌더한다.

**#320이 해결해 준 것** — Markdown 표 확장 문제가 사라졌고(HTML이므로),
"중요한 내용은 9pt 이상 + 본문 대비 20% 크게" 요구를 CSS로 정확히 구현할 수 있게 됐다.

| 4 | 민감정보 처리 동의 | `drafts/04-...` | 타임라인 첫 생성 | 초안 |
| 5 | 개인정보 국외 이전 동의 | `drafts/05-...` | 타임라인 첫 생성 | 초안 |

Google Play 등재정보의 개인정보처리방침 URL도 이 페이지를 쓴다.

## 3. 확정된 결정

| 결정 | 내용 | 근거 |
|---|---|---|
| AI 전송 성격 | **제3자 제공**(위탁 아님) | 법무 자문 |
| 동의 강제 | 필수 동의. 미동의 시 **타임라인 생성만** 차단, 로그인·열람·탈퇴는 허용 | 비례성 |
| gate 위치 | `TIMELINE_FIRST_CREATE` 유지. `LOGIN`으로 올리지 않는다 | 위와 같음 |
| 탈퇴 후 파기 | **접수일로부터 5일 이내** | 복구 기능·재가입 악용 여지 없음 |
| 접속기록 보존 | **수집일로부터 6개월** | 위치정보 확인자료와 주기 통일 |
| LLM 구성 | **Bedrock 단일** — OpenAI + Amazon Nova. Gemini는 Bedrock provider 목록에 없어 제외 | AWS 공식 문서 |
| 항목 선택 | 사진·좌표·알림·일정을 회원이 **건별로** 보고 고른다. 선택 안 한 항목은 서버에 오지 않는다 | |
| 위치 약관 | 위치정보법은 별개 법이라 별도 약관 추가 | |
| 향후 항목 추가 | 새로 추가되는 수집 항목은 **선택 동의(`required=false`)** 로 만든다. 필수로 만들면 재동의가 기존 사용자를 막는다 | |

## 5. 결정이 필요한 것

1. **건강 항목(걸음·이동거리·수면) 제거 여부**
   - 빼면 민감정보가 감정 하나로 줄고, Play 제한 권한 **Health Connect·신체 센서 2개를 회피**한다.
   - 이동 거리는 `MovementPayload.distanceMeters`와 이미 중복이다.
   - 빼기로 하면 서버가 `ItemType.HEALTH`를 거절해야 "수집하지 않음"이 참이 된다.
2. **#1에 표준약관 5개 반영** — 신원정보 게시, 중요내용 별도 확인, 회원 통지 방법,
   자격상실 전 30일 소명, 광고성 정보 수신 동의.
3. **서비스 변경 조항** — 표준 제21조 ③(동의 받고 거절자에게 변경 전 서비스 제공)은 지킬 수 없다.
   "30일 전 공지 + 해지권"으로 대체하기를 권한다.
4. **개정 미동의 시 손해배상**(표준 제5조 ③) 채택 여부.
5. **AgentCore 구성** — Memory 사용 여부와 `eventExpiryDuration`, Evaluations 사용 여부
   (서울이 global cross-region inference 소스라 **전 세계 리전**으로 나간다), cross-region을 끌지.

## 6. 코드가 따라와야 할 것

| 작업 | 이유 |
|---|---|
| `TermType`에 `LOCATION_BASED_SERVICE_TERMS` 추가 | seed 후 enum을 바꾸면 stage 전체가 fail-open |
| `TermType.PRIVACY_POLICY` 이름 재검토 | 실제 문서는 "수집·이용 동의"인데 literal이 처리방침이라 혼란. seed 전이 유일한 변경 기회 |
| 개인위치정보 이용·제공사실 확인자료 기록 | #6 제10조가 6개월 보관을 약속하는데 그런 기록 자체가 없다 |
| #302 파기 워커 | #1 제15조와 #2·#4·#8의 보유기간이 전부 이 워커를 전제. **실패가 3일 이상 지속되면 약관 위반**이라 실패 알림 필수 |
| 정적 페이지 게시 파이프라인 | `laimory.app/terms/{slug}/{version}` 호스팅 |

## 7. Android에 전달할 스펙

- 선택 해제한 항목은 **업로드도 하지 말 것**. 클라가 전부 올리고 화면에서만 거르면 #2의 문구가 거짓이 된다.
- 동의 체크박스 **기본값 체크 금지**. 미리 체크된 동의는 능동적 의사 확인이 아니라 무효다.
- 약관 전문 화면은 **확대 가능**해야 한다.
- 중요한 내용(민감정보·보유기간·제공받는 자)은 **9pt 이상 + 본문 대비 20% 크게, 색·굵기·밑줄로 구분**.
  게시 HTML에서 CSS로 처리한다.
- 처리방침은 로그인 전에도 접근 가능해야 한다.

## 9. 확인되지 않은 근거

아래 조항은 원문 대조에 실패했다. 법률 검토에서 반드시 짚어야 한다.

- #1 제3조 ③④ — 개정 공지 7일/30일의 근거 조문, 동의 의제 조항의 유효성
- #1 제16조 ②③ — 면책의 "고의 또는 중대한 과실" 단서 수위
- #1 제17조 ③ — 관할을 민사소송법에 맡기는 것의 적정성
- 각 동의서의 필수 기재사항 근거 조문 번호(항목 구성 자체는 실무 통용 기준으로 확인)

**또 하나** — 국외 이전이 위탁·보관 목적이면 처리방침 공개로 동의를 갈음할 수 있다.
AI 전송을 제3자 제공으로 규정한 판단 하나에 #5의 존폐가 달려 있다. 정식 검토에서 재확인할 항목이다.
